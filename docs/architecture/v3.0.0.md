# Faultless Framework Architecture - v3.0.0 (2017)

## Overview

This document describes the architecture of Faultless v3.0.0, focusing on advanced middleware system and enhanced error handling, inspired by modern microservice architecture's middleware chain, circuit breaker, rate limiting, and error handling patterns.

## New Features in v3.0.0

### @Faultless/breaker - Circuit Breaker Pattern

#### Core Circuit Breaker (`circuit-breaker.ts`)
- **Three States**: Closed → Open → Half-Open → Closed
- **Configurable Thresholds**: Failure threshold, timeout, reset timeout
- **Fallback Support**: Graceful degradation when open
- **Event Emission**: State changes, successes, failures
- **Metrics Integration**: Prometheus metrics support

```typescript
const breaker = createCircuitBreaker({
  name: 'user-service',
  threshold: 5,
  timeout: 30000,
  resetTimeout: 10000,
  fallback: async (error) => ({ degraded: true }),
  isFailure: (error) => error.code !== 'VALIDATION_ERROR',
});

const result = await breaker.execute(async () => {
  return await externalApi.call();
});
```

#### HTTP Middleware Integration (`circuit-breaker-middleware.ts`)
- Per-route circuit breaker configuration
- Automatic key generation from route/method
- Custom fallback handlers
- Response headers: `X-Circuit-Breaker`, `Retry-After`
- Route exclusion patterns

```typescript
app.addHook('preHandler', createCircuitBreakerMiddleware({
  breaker: myBreaker,
  keyGenerator: (req) => `${req.method}:${req.url}`,
  fallback: async (req, reply, error) => {
    reply.status(503).send({ error: 'Service degraded' });
  },
  excludedPaths: ['/health', '/metrics'],
}));
```

#### Metrics (`metrics.ts`)
- Prometheus metrics for state, requests, successes, failures, rejections, latency
- Automatic instrumentation via event listeners

### @Faultless/limit - Rate Limiting

#### Core Rate Limiter (`rate-limiter.ts`)
- **Multiple Algorithms**: Fixed window, Sliding window, Token bucket, Leaky bucket, Sliding window log
- **Pluggable Stores**: Memory (default), Redis, Cluster
- **Flexible Configuration**: Window size, max requests, key prefixes, skip conditions
- **Event Emission**: Limited/allowed events

```typescript
const limiter = createRateLimiter({
  name: 'api',
  windowMs: 60000,
  max: 100,
  store: new RedisRateLimitStore({ client: redis }),
  keyPrefix: 'ratelimit:',
});

const result = await limiter.consume('user:123');
```

#### HTTP Middleware (`rate-limiter-middleware.ts`)
- Standard rate limit headers (`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`, `Retry-After`)
- Custom key generators
- Skip functions for whitelisting
- Custom handlers for limited responses

```typescript
app.addHook('preHandler', createRateLimitMiddleware({
  limiter: apiLimiter,
  keyGenerator: (req) => `${req.ip}:${req.method}:${req.url}`,
  skip: (req) => req.url.startsWith('/health'),
  handler: async (req, reply, result) => {
    reply.status(429).send({ error: 'Rate limited' });
  },
}));
```

#### Strategies (`strategies.ts`)
- **Fixed Window**: Simple, memory-efficient
- **Sliding Window**: Smoother limiting
- **Token Bucket**: Burst handling
- **Leaky Bucket**: Constant rate
- **Sliding Window Log**: Precise but memory-intensive

#### Stores (`store.ts`)
- **MemoryStore**: In-memory with automatic cleanup
- **RedisStore**: Distributed rate limiting with Lua scripts
- **ClusterStore**: Multiple store failover

### Enhanced Middleware System (`middleware.ts`)

#### New Middlewares
- **Retry Middleware**: Exponential backoff with configurable retryable errors
- **Timeout Middleware**: Request-level timeout with `REQUEST_TIMEOUT` error
- **Enhanced Auth Guards**: JWT, Role-based, API Key
- **Enhanced Interceptors**: Logging, Transform, Cache
- **Enhanced Pipes**: Validation, ParseInt/Float/Bool/Array, Default Value, Transform
- **Enhanced Filters**: All Exceptions, Not Found, Validation

```typescript
registerDefaultMiddlewares(app, {
  cors: true,
  helmet: true,
  requestId: true,
  logging: true,
  rateLimit: { limiter: apiLimiter },
  circuitBreaker: { breaker: mainBreaker },
  timeout: 30000,
  retry: { retries: 3, delay: 100, backoff: 'exponential' },
});
```

### Error Handling Enhancements

#### Error Classification (`core/errors.ts`)
- **Retryable Errors**: `SERVICE_UNAVAILABLE`, `GATEWAY_TIMEOUT`, `CIRCUIT_BREAKER_OPEN`, `TOO_MANY_REQUESTS`, `DEPENDENCY_ERROR`
- **Non-Retryable**: Validation, Not Found, Unauthorized, Forbidden, Conflict
- **isRetryableError()**: Helper for retry logic

#### Structured Error Responses
```json
{
  "error": "ERROR_CODE",
  "message": "Human readable",
  "details": {},
  "requestId": "req_xxx",
  "timestamp": "2024-01-01T00:00:00.000Z"
}
```

### Health Checks (`http/src/health/`)

#### HealthCheckService
- **Liveness**: `/health/live` - Process alive
- **Readiness**: `/health/ready` - Ready to serve traffic
- **Full Health**: `/health` - Detailed component health
- **Configurable Timeout**: Per-check timeout
- **Overall Status**: ok / degraded / error

#### Built-in Indicators
- **MemoryHealthIndicator**: Heap usage, RSS thresholds
- **DiskHealthIndicator**: Disk space monitoring
- **DatabaseHealthIndicator**: Custom connection check
- **RedisHealthIndicator**: PING check
- **HttpHealthIndicator**: External HTTP endpoint
- **CustomHealthIndicator**: Arbitrary async checks

```typescript
HealthModule.forRoot({
  includeDetails: true,
  timeout: 5000,
  indicators: [
    new MemoryHealthIndicator({ heapUsedThreshold: 0.8 }),
    new DatabaseHealthIndicator({
      name: 'postgres',
      check: async () => await db.query('SELECT 1'),
    }),
    new RedisHealthIndicator({ name: 'redis', client: redis }),
    new HttpHealthIndicator({ name: 'external-api', url: 'https://api.example.com/health' }),
  ],
});
```

## Design Decisions

1. **Separate Packages** - Breaker and Limit as independent packages for reusability
2. **Event-Based** - Circuit breaker emits events for monitoring/debugging
3. **Pluggable Algorithms** - Rate limiter supports multiple algorithms
4. **Distributed Ready** - Redis store for multi-instance deployments
5. **Health Check Standards** - Follows Kubernetes liveness/readiness patterns
6. **Graceful Degradation** - Circuit breaker fallback for partial functionality
7. **Standard Headers** - Rate limiting uses standard HTTP headers
