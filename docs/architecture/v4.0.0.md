# Faultless Framework Architecture - v4.0.0 (2018)

## Overview

This document describes the architecture of Faultless v4.0.0, focusing on service discovery and client-side load balancing, inspired by modern microservice architecture's service discovery (discov), resolver, and zrpc load balancing.

## New Features in v4.0.0

### @Faultless/discovery - Service Discovery & Load Balancing

#### Service Registry (`service-registry.ts`)
- **In-Memory Registry**: For development/testing
- **Service Registration**: Register with metadata, tags, health checks
- **Heartbeat Mechanism**: Periodic heartbeats with TTL
- **Event Emission**: Register/deregister/heartbeat events
- **Extensible Base Class**: For custom registry implementations

```typescript
const registry = createInMemoryRegistry();

const instance = await registry.register({
  name: 'user-service',
  address: 'localhost',
  port: 3000,
  metadata: { version: '1.0.0', zone: 'us-east-1' },
  tags: ['api', 'users'],
  healthCheck: { type: 'http', interval: 10000, path: '/health' },
  heartbeatInterval: 5000,
});

// Later...
await registry.deregister(instance.id);
```

#### Service Discovery (`service-discovery.ts`)
- **Multiple Backends**: etcd, Consul, Kubernetes, Static, Memory
- **Watch Mechanism**: Real-time instance updates
- **Namespace Support**: Multi-tenancy isolation
- **TLS/Authentication**: Secure connections
- **Automatic Reconnection**: Resilient to backend failures

```typescript
// etcd discovery
const discovery = createServiceDiscovery({
  type: 'etcd',
  endpoints: ['localhost:2379'],
  serviceName: 'user-service',
  namespace: 'production',
});

// Consul discovery
const discovery = createServiceDiscovery({
  type: 'consul',
  endpoints: ['localhost:8500'],
  serviceName: 'user-service',
});

// Kubernetes discovery
const discovery = createServiceDiscovery({
  type: 'kubernetes',
  endpoints: [],
  serviceName: 'user-service',
  namespace: 'default',
});
```

#### Load Balancers (`load-balancer.ts`)

| Strategy | Description | Use Case |
|----------|-------------|----------|
| **round-robin** | Sequential distribution | General purpose |
| **weighted-round-robin** | Weight-based distribution | Heterogeneous instances |
| **least-connections** | Fewest active connections | Long-lived connections |
| **p2c (Power of Two Choices)** | Pick 2 random, choose least loaded | High throughput, low latency |
| **consistent-hash** | Hash-based with virtual nodes | Session affinity, caching |
| **random** | Pure random selection | Simple, stateless |
| **ip-hash** | Client IP based hashing | Sticky sessions |

```typescript
const lb = createLoadBalancer({
  name: 'api-service',
  discovery: myDiscovery,
  strategy: 'p2c', // Recommended for most cases
});

const instance = await lb.pick('user-123'); // Consistent hash key
```

**Power of Two Choices (P2C)** - Default recommendation:
- Picks 2 random instances
- Chooses the one with fewer connections
- O(1) complexity, near-optimal distribution
- Used by Google, Netflix, and other tech companies

**Consistent Hash** - For session affinity:
- Virtual nodes for better distribution
- Weights support for heterogeneous clusters
- Automatic rebalancing on instance changes

#### Resolver (`resolver.ts`)
- **Unified Interface**: Combines discovery + load balancing
- **Target Parsing**: `scheme://service-name?params`
- **Builder Pattern**: Extensible resolver builders
- **Client Integration**: HttpClient with automatic resolution

```typescript
// Direct resolver (static)
const resolver = await createResolverFromTarget('direct://user-service');

// etcd resolver with P2C
const resolver = await createResolverFromTarget(
  'etcd://user-service?endpoints=localhost:2379&lb=p2c&namespace=prod'
);

// Consul resolver
const resolver = await createResolverFromTarget(
  'consul://order-service?endpoints=localhost:8500'
);

// Kubernetes resolver
const resolver = await createResolverFromTarget(
  'kubernetes://payment-service?namespace=production'
);
```

#### Kubernetes Integration (`kubernetes.ts`)
- **Service/Endpoints Watching**: Real-time pod discovery
- **Label/Field Selectors**: Flexible filtering
- **Ingress Parsing**: HTTP routing rules
- **Pod Metadata Extraction**: Labels, annotations, IP, node

```typescript
const k8s = createKubernetesDiscoveryClient();

const services = await k8s.listServices('default', 'app=myapp');
const endpoints = await k8s.listEndpoints('default', 'app=myapp');
const instances = endpointsToInstances(endpoints, servicePorts);
```

### @Faultless/http v4.0.0 Enhancements

#### HttpClient (`client.ts`)
- **Automatic Service Resolution**: Uses Resolver for endpoint discovery
- **Built-in Resilience**: Circuit breaker, rate limiting, retry, timeout
- **Multiple HTTP Methods**: GET, POST, PUT, DELETE, PATCH
- **Connection Management**: Reuses Fastify's connection pool

```typescript
const client = new HttpClient({
  serviceName: 'user-service',
  resolver: {
    discovery: { type: 'etcd', endpoints: ['localhost:2379'], serviceName: 'user-service' },
    loadBalancer: { strategy: 'p2c' },
  },
  circuitBreaker: { enabled: true, threshold: 5, resetTimeout: 10000 },
  rateLimit: { enabled: true, max: 100, windowMs: 60000 },
  retry: { retries: 3, delay: 100, backoff: 'exponential' },
  timeout: 30000,
}, fastify);

await client.start();
const response = await client.get('/users/123');
```

#### HttpClientFactory
- **Multi-Service Management**: Create/manage multiple clients
- **Lifecycle Management**: Start/stop all clients
- **Singleton Pattern**: One client per service name

### Health Checks Integration
- **Service Registry Heartbeats**: Automatic health reporting
- **Discovery Health**: Endpoint availability checks
- **Load Balancer Health**: Connection counting, failure detection

## Design Decisions

1. **Client-Side Load Balancing** - No central proxy, reduces latency and single point of failure
2. **P2C as Default** - Near-optimal, simple, used by major tech companies
3. **Resolver Pattern** - Clean separation of discovery and load balancing
4. **Extensible Builders** - Easy to add new discovery backends
5. **Kubernetes Native** - Uses Endpoints API for pod-level discovery
6. **Event-Driven Updates** - Watch mechanisms for real-time updates
6. **Graceful Degradation** - Works with static config for development
